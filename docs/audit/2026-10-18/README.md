## 问题记录

### AUD-001（P1，已修复）：AI 配置保存覆盖正在刷新的登录令牌

- 来源：`AppConfigProvider.updateAiConfig()` 调用 `AppConfig.save()`，后者同时写登录凭据。凭据字符串在加入共享写队列前捕获，可能排在刷新写入后保存过期值。
- 复现：暂停刷新令牌的安全存储写入，保存 AI 配置，再释放写入。旧代码内存为 `new/rotated`，磁盘却为 `old/refresh`，重启丢失轮换后的令牌。
- 修复：新增独立 AI 配置保存入口，保留原有 AI 密钥与 URL 的原子提交和回滚；设置保存不再读取或写入 Cookie、登录令牌，减少无关存储访问。
- 回归：`test/audit_config_integrity_test.dart` 两项测试在修复前失败，修复后通过；检查磁盘与内存一致、重启恢复以及 AI 设置不触碰认证存储。相邻定向回归共 48 项通过。

### AUD-002（P2，已修复）：缓存书架绕过已取消请求的检查

- 复现：移动端验证产生可复用快照后，传入已经取消的令牌调用书架读取。旧代码返回成功并消耗快照。
- 修复：读取或清理快照前检查调用方取消状态；重试可以继续使用尚未消耗的快照。
- 回归：`test/audit_cached_cancellation_test.dart` 检查取消异常及重试零额外网络请求。

### AUD-003（P2，已修复）：关闭客户端的迟到读取清除新会话缓存

- 复现：关闭旧客户端，新客户端完成验证后再调用旧客户端的书架读取。旧代码先清空全局快照，随后才由 Dio 拒绝请求，导致正常客户端额外联网。
- 修复：先拒绝已关闭客户端，再访问共享快照。
- 回归：`test/audit_cached_cancellation_test.dart` 在修复前出现“额外请求”，修复后保留“验证快照”；第二轮相邻定向回归共 70 项通过。

### AUD-004（P2，已修复）：手机卡片弹层无法随内容拖动展开/收起

- 原因：`DraggableScrollableSheet` 提供的控制器没有传给卡片内容的滚动视图。
- 复现：手机短卡片和长卡片向上拖动 220 像素后，预览区域顶部始终停在 216 像素，两项手势回归均失败。
- 修复：将弹层控制器传入预览的滚动视图；桌面预览继续使用自身滚动位置。
- 回归：短内容可展开和收起，长内容先展开再滚动正文、回顶后可收起；全部 45 项卡片生命周期测试通过，随后 770 项全量门禁通过。

### AUD-005（P3，已修复）：并发 flush 被不符合真实流行为的测试模拟掩盖

- 原因：测试流允许同时执行两次 `flush()`，真实 Dart `IOSink` 会抛出 `StreamSink is bound to a stream`。已有导出主流程按顺序 await，未发现普通界面操作会并发触发此问题；这是写入器并发契约及测试准确性问题。
- 复现：`test/audit_export_sink_test.dart` 使用真实临时文件，并发两次刷新后关闭，旧实现失败。
- 修复：并发刷新共享正在进行的底层刷新；关闭等待共享操作；合并重复刷新也减少底层调用。
- 回归：验证真实内容完整、Windows 文件句柄释放后可重命名、所有等待者收到原始刷新错误；修正旧模拟测试的错误预期。写入器、文件发布及内存边界共 34 项回归通过，补充失败共享断言后 3 项写入器测试通过。

### AUD-006（P2，已修复）：书架显示密度未处理存储失败及重复保存

- 复现：偏好读取抛错会产生未处理异步异常并永久禁用密度选择；旧数据类型损坏也会抛错；写入返回 false 时界面仍切到新密度，写入抛错没有错误提示。六项异常/并发回归在修复前失败。
- 修复：读取失败保留默认三列并允许重新选择；重新读取持久化值，避免失败写入污染内存缓存；写入成功后才应用新布局，失败时提示重试；保存期间禁止重复写入，销毁后不更新界面。
- 回归：`test/audit_bookshelf_state_test.dart` 覆盖读取异常、损坏旧值、写入返回 false/抛错、重建恢复、重试，以及待写入时销毁后的成功/失败、等待打开偏好存储时销毁不写入。另用 Widget 测试中的 Android 样式下拉手势验证空书架和一条记录均能同步，排除短列表刷新疑点，没有为此修改实现。9 项通过；不是 Android 真机测试。

### AUD-007（P2，已修复）：Windows 安装失败留下混合版本

### AUD-010（P2 性能，已优化）：混合笔记搜索未利用候选主键读取

- 真实查询计划显示：外层关联 EXISTS 导致 notes/bookmarks 按时间索引扫描并逐条查询三元组索引；聚合 COUNT 的 UNION 也会全表读取。
- 将三元组候选筛选放进两个 UNION 分支，各自按来源、主键读取候选，再保留完整 LIKE 校验、排序、分页、收藏及书籍筛选。不新增数据库索引或迁移，不使用旧 SQLite 不支持的行值语法。
- 新增查询计划与跨来源同 ID 回归，旧实现失败；优化后列表、计数、摘要三个查询均按主键取候选。相邻 48 项数据库、旧 SQL 语法、分页及导出测试通过。
- 基准初步结果：2 万条的选择性中文搜索（计数 + 首屏）中位耗时从 379.639 ms 降至 1.502 ms；5 万条从 744.524 ms 降至 4.198 ms。该对比是本机合成数据的 JIT 测量，不能换算为所有搜索或手机端提速比例。

### AUD-011（P2 性能，已优化）：导出快照为每本书重扫全部记录

- 5 万条、约 50 MB 输出的导出初测耗时约 67 秒。分阶段测量定位到书名 UPDATE：2,000 条 / 200 本书场景该语句耗时 1,869 ms，而快照读取仅 25 ms。
- 实际计划显示，每本书执行关联子查询，扫描全部 notes/bookmarks 并临时排序；原“按批读取”只能约束 Dart 内存，不能避免这段重复扫描。
- 改为先检查是否存在该书的划线，再通过 `book_id, created_at, id` 索引选择相应来源的第一条标题；保留划线优先、时间与 ID 排序、NULL/空字符串规则，不能用 COALESCE 擅自改变这些行为。
- 新增 `test/audit_export_title_test.dart`，旧查询计划断言失败，优化后结果及索引计划通过；相邻 75 项导出、取消、清理恢复、快照及数据库回归通过。相同小库分阶段检查标题语句降至 1 ms，完整快照由 1,926 ms 降至 44 ms；最终大库数据另列。
